### Q-2 — Required: `kubectl run --env-from` does not exist (E.0.4, X-E.8)

`kubectl run` accepts `--env=KEY=VALUE` and `--overrides=<json>` only (verified with `kubectl run --help`); 06 X-E.23 itself states "`--env-from` is not available on `kubectl run`" and uses `--overrides`. Yet 05 E.0.4 L484 (`kubectl -n aeq run pgdump … --env-from secret aeq-postgres -- sh -c 'pg_dump -Fc "$DATABASE_URL"'`) and 06 X-E.8 (`kubectl -n geekonomy run psql … --env-from secret geekonomy-secrets -- sh -c 'psql "$DATABASE_URL" -Atf -'`) cannot run; X-E.5 (aeq dump present) depends on E.0.4 and H.2 step 1 depends on X-E.8. Fix: the X-E.23 pattern — e.g. `kubectl -n aeq run pgdump --rm -i --restart=Never --image=postgres:16-alpine --overrides='{"spec":{"containers":[{"name":"pgdump","image":"postgres:16-alpine","command":["sh","-c","pg_dump -Fc \"$DATABASE_URL\""],"envFrom":[{"secretRef":{"name":"aeq-postgres"}}]}]}}' > aeq-$DATE.dump` (same shape for X-E.8 with `geekonomy-secrets` and the `psql` command, stdin still forwarded by `-i`). The secret keeps being consumed inside the pod; nothing is printed.

### Q-3 — Required: `gcloud storage hash --sha256` does not exist (05 §5 conventions, X-E.1 and every row that says "hash check")

The command's flags are `--hex`, `--skip-crc32c`, `--skip-md5`, `--additional-headers`, `--decryption-keys`; it computes **MD5 and CRC32C only** (reference page verified). 05 §5 L477 ("every upload is followed by `gcloud storage hash --sha256 gs://…/<obj>` compared against the local `sha256sum`") and 06 X-E.1 (`gcloud storage hash --sha256 … \| grep -i sha256`) — inherited by X-E.2, X-E.4 ("as X-E.1"), X-E.5 ("hash check") — therefore fail with `unrecognized arguments`, which under ground rule 2 halts Phase E at its first integrity check. Fix (keep the local `.sha256` sidecar as the archival record): compare **CRC32C**, which GCS holds for every object including composite uploads — `gcloud storage hash --hex --skip-md5 <local file>` vs `gcloud storage hash --hex --skip-md5 gs://…/<obj>` → equal `crc32c_hash` — or read the object back: `gcloud storage cat gs://…/<obj> | sha256sum` = the sidecar (fine for dumps of a few GB, not for the archive buckets). Do **not** rely on MD5: `gcloud storage cp` may upload large files as parallel-composite objects, which carry no `md5Hash`.
