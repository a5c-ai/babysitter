# 02 — Source origins of every Azure-deployed system (2026-09-16)

Companion to [01-azure-inventory.md](./01-azure-inventory.md) / [01-azure-inventory.json](./01-azure-inventory.json). For each of the 26 inventory systems this document names the **git origin** that builds and deploys it (workflow job, helm chart, terraform module, manifest, script), who triggers it, its status, and every Azure-specific coupling in that source. Machine-readable twin: [02-source-origins.json](./02-source-origins.json).

Method: every candidate repo was shallow-cloned into `.a5c/workspaces/azure-to-gcp/<repo>` (gitignored) and read directly; `gh search code`, `gh api`, `helm get values`, `kubectl get` (read-only) and the local babysitter checkout (branch `staging`, HEAD `57b13a4c5`) were used to cross-check. File references are `repo:path:line` at the commit listed in §0. Nothing was copied out of the cluster; no secret values appear here.

Status legend — **ACTIVE**: a push to the origin still deploys the running thing. **STALE**: source exists but the origin has not deployed for months and/or the running artifact drifted from HEAD. **ORPHAN**: no source found in any a5c-ai repo. **MANUAL**: deployed by hand (portal, CLI, one-off script) with no CI path.
